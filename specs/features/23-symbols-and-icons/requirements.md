# Feature 23: Symbols and icons for a tile. Requirements

"Tile" and "cell" mean the same thing, as PRODUCT.md says. "The tile dialog" is the dialog of edit mode that adds or edits a cell. "A picture" is a Mulberry symbol or a Lucide icon. "A cell that speaks" speaks a phrase, and "a cell that opens a board" leads to a board.

The numbers below were measured on 2026-11-24. Mulberry 3.6.1 holds 3,436 symbols, which take 33.8 MB as files. Lucide 1.77.0 holds 2,098 icons, whose drawings take 0.47 MB as one JSON file. The roadmap guessed 3,400 and 1,600.

## What the feature must do

1. In the tile dialog the caregiver gives a tile a Mulberry symbol or a Lucide icon. Source: roadmap.md, feature 23. PRODUCT.md, Capabilities (cell contents).
2. The caregiver searches all the Mulberry symbols and all the Lucide icons by name. Source: roadmap.md, feature 23, and the user's request of 2026-11-24.
3. The tile dialog stays a caregiver screen that scanning does not reach. A cell with any picture is still reached and picked by single switch scanning. Source: roadmap.md, the two rules for every feature. PRODUCT.md, Principles 2 and 5.
4. The tile dialog and the boards pass WCAG 2.2 Level AA with the new pictures. Source: roadmap.md, the two rules for every feature.
5. The picture of a tile is stored in the set, in the shape of `cells.json`, and is saved and synced as feature 9 does it. Source: CLAUDE.md, Rules. tech-stack.md, Data.
6. The app credits Mulberry and Lucide, and it ships the licence of each. The Mulberry files are not changed apart from their names. Source: tech-stack.md, Design reference.
7. The feature adds no cloud service. Source: CLAUDE.md, Rules.
8. **Patent check.** The search compares the typed text with the names of the pictures. It generates no content and no suggestions, and it does not rank by the label, the phrase or the user. The patent check of tech-stack.md, Patents, does not apply.

## The open questions of the roadmap

Each answer below is my proposal. The user confirms them by approving the plan.

9. **Where the Mulberry set comes from and how it ships.** The symbols come from the file `mulberry-symbols.zip` of the Mulberry release 3.6.1 on GitHub. Mulberry has no npm package. A script copies the files into `public/symbols/`, and they are committed. The 98 Mulberry symbols that the app already has keep their file names and their names, so no stored tile breaks. The folder grows from 0.9 MB to about 34 MB, and so do the repo, the Mac app and the iPad app. The browser fetches a symbol only when a cell or the dialog shows it.
10. **The file names of the symbols.** A new file gets its Mulberry name in lower case, with each run of other characters turned into one hyphen, so `Advent_calendar.svg` becomes `advent-calendar.svg`. That fits the rule of `loadBoards` for a symbol file. A name that is already taken gets a number at its end, such as `drink-2.svg`. This happens for `close-to`, and for `drink`, `hot` and `open`, which the app already uses for other Mulberry pictures. `ATTRIBUTION.txt` lists every file with its original name.
11. **The names of the symbols.** The name of a new symbol is its Mulberry file name with each underscore turned into a space, such as "Advent calendar" and "drink , to". `src/data/symbols.json` lists all 3,437 symbols, which are the 3,436 of Mulberry and the stop symbol of Symple.
12. **Where the Lucide set comes from and how it ships.** The package `lucide-static`, version 1.77.0, is added as a development package. That is the version the app's inline icons were copied from. A script writes the drawings of all 2,098 icons to `src/data/lucide.json`, and the file is committed. The app draws each icon inline from that file, so it still has no icon package at run time and an icon still takes the colour of its cell. The line in tech-stack.md that says the app has no icon package changes to say this.
13. **How a tile stores an icon.** The field `icon` of a tile takes one of the 18 names of today, or `lucide:` followed by a Lucide name, such as `lucide:apple`. The 18 names keep their drawings. The prefix is needed because six of the 18 names, which are `heart`, `keyboard`, `trash`, `check`, `cross` and `group`, are also Lucide names, and some of those have another drawing. `loadBoards` checks the form of the name and not whether Lucide has it. An icon that Lucide does not have draws nothing, and the cell shows its label.
14. **Whether each kind of cell takes each kind of picture.** It does. A cell that speaks takes a symbol, an icon or no picture. A cell that opens a board takes a symbol or an icon, and it must have one. A cell with a symbol has the style `symbol` whatever it does. A cell that speaks with an icon also has the style `symbol`, and it draws the icon where the symbol would be. A cell that opens a board with an icon keeps the styles Bleed, Signage and Stage. `loadBoards` now accepts a `symbol` tile that names an icon and no symbol.
15. **How the dialog lists about 5,500 pictures without slowing down.** The list draws at most 60 pictures. A Show more button adds 60 more. No line says how many are shown or how many match, which the user decided on 2026-11-24. The symbol images load lazily. The two lists of names are not in the first download of the app: `symbols.json` and `lucide.json` are each fetched the first time they are needed. `lucide.json` is also fetched when a board shows a cell with a `lucide:` icon.
16. **What the larger sets do to the size of the app.** The first download does not grow, and check A1 of validation.md, the build, proves it against the budget of `angular.json`. The two lists add about 0.7 MB that is fetched on demand. The symbols add about 33 MB of files. On the web a symbol that was never shown needs the network, as it does today.

## Things neither source covers

These are my choices. Each one can change before implement.

17. **One Picture field.** The Symbol field of a cell that speaks and the Icon field of a cell that opens a board become one field named Picture. It holds a box named "Find a picture", a choice of Symbols or Icons, the list, and Show more. The box has no row of its own for its name, which the user decided on 2026-11-24. The name is the placeholder of the box and its name for a screen reader. A cell that speaks starts on Symbols, and a cell that opens a board starts on Icons. An edit starts on the kind of picture the cell has. The user changed the layout on 2026-11-24: the name or label, the phrase, the style and the colour sit under the preview on the left, and the Picture field takes the right side with Cancel and Add or Save under it. The user changed the choice of Symbols or Icons on 2026-11-25 from two boxes to a native drop down that lies to the right of the box on the same row, as high as the box, and is named "Kind of picture" for screen readers.
18. **The search.** The text is cut into words. A picture matches when its name holds every word, without regard to case. Names that begin with the text come first, and the rest follow in the order of the alphabet. An empty box lists every picture. The text stays when the caregiver changes between Symbols and Icons. The options of the drop down "Kind of picture" show no number of pictures, which the user decided on 2026-11-24 for the two boxes that the drop down replaced on 2026-11-25. No line counts the pictures. A note at the end of the list says when no picture has the name, when the pictures are loading and when they could not be loaded.
19. **The names of the icons.** An icon is named by its Lucide name with each hyphen turned into a space, such as "arrow down". The 12 icons that a board can take today keep the names the dialog gives them, such as "Grid".
20. **The chosen picture.** The picture that the cell has is always first in the list, whatever the box holds, so the caregiver sees what is chosen. A cell that speaks also has "No picture" in the list at all times.
21. **The Style field.** A cell that opens a board shows the Style field only while its picture is an icon, because a symbol has one style. The user changed the Style field to a drop down on 2026-11-24, with the options Cropped Icon, Icon in Circle and Centered Icon for the stored styles `bleed`, `signage` and `stage`.
22. **A cell that keeps its look.** An edit that does not change the picture keeps the style of the tile, as the edit of feature 9 does for a tile with an icon.
23. **The credits.** The About lines of the settings panel stay as they are. `README.md` and `ATTRIBUTION.txt` name the Mulberry release and the number of files.
24. **File names.** `scripts/import-mulberry.mjs` copies the symbols and writes `symbols.json` and `ATTRIBUTION.txt`. `scripts/import-lucide.mjs` writes `lucide.json`. `scripts/check-pictures.mjs` checks the two lists against the files. `src/app/cells/icon-set.ts` loads the Lucide drawings. `src/app/edit/picture-search.ts` holds the search as a plain function, and `src/app/edit/picture-list.ts` loads the two lists of names for the dialog.
25. **A drop on Add column.** In edit mode a cell that is dragged onto Add column, or onto Add row in the rows layout, and let go there goes into a new group at the end of the board, as one change. A press on Add column while a cell is picked up does the same, and a press with nothing picked up adds an empty group as before. Add column shows a solid border while it would take the cell. The group that the cell leaves stays, and it is empty when the cell was its only one. When the board has no room for another group, the drop and the press move nothing, and the status line says that the board has no room. After a move the status line says, for example, "Help moved to a new column", and the focus goes to the Edit button of the cell. The user asked for this on 2026-11-25.

## Left for later features

- The search does not use the Lucide tags or the Mulberry categories. The roadmap asks for a search by name.
- The caregiver cannot add a symbol or a photo of their own.
- The symbol files are not made smaller. A changed symbol would have to be shared under CC BY-SA 4.0.
- Feature 10, the Mac app, still has to check that the symbol images load in the packaged app.
